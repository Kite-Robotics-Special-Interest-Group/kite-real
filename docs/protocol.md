# 真机采集与评测协议

## 1. 采集前（一次性）

| 项 | 要求 | 记录在 |
| --- | --- | --- |
| 相机 | 固定机位，分辨率、焦距、曝光写死 | `meta.json` 的 `camera` |
| 标定 | 末端与相机的相对位姿，误差 < 5 mm | `calib.json` |
| 控制频率 | 10–20 Hz，**先定频率再定动作块长度** | `meta.json` 的 `control_hz` |
| 夹爪语义 | 0/1 = 开/合指令，或位置（米）——**写清楚，别混** | `meta.json` 的 `gripper` |
| 动作空间 | 优先关节空间；若用末端位姿，必须固定臂形约束 | `meta.json` 的 `action_space` |

> 仿真阶段踩过的坑：夹爪标签存成"手指位置（米）"，模型学成常数；动作块 30 步只覆盖 0.06 s，模型学成"原地不动"。真机上这两类错误同样会发生，且更难发现。

## 2. 每条 episode

1. 复位到统一初始位姿（记录在 `meta.json`）
2. 按任务指令执行，录制：
   - 每控制周期一张主视角（+ 腕部若有）
   - 关节角、夹爪状态、末端位姿
   - 时间戳（用于核对是否掉帧）
3. 结束判定：
   - 成功：物体到位且夹爪已释放
   - 失败：超时（建议 30 s）/ 掉落 / 人工中止
4. 立刻写 `meta.json`，**不要事后补**——失败原因当场记

## 3. 失败必须标注类型

| 类型 | 含义 |
| --- | --- |
| `miss` | 没碰到目标 |
| `slip` | 夹住但滑脱 |
| `wrong_place` | 放偏 |
| `stall` | 中途停滞（仿真里分拣就是这个） |
| `other` | 其它，写备注 |

失败类型比成功率更有信息量：`slip` 说明夹爪/摩擦问题，`stall` 说明策略在某个状态下卡住。

## 4. 评测协议

- 每个扰动档位 **20 条**，同一批初始状态
- 扰动用物理手段实现，不用后期处理（否则与离线扰动不对应）：
  - 模糊 → 调焦或加雾面滤镜
  - 遮挡 → 挡板/贴纸，放在固定像素区域
  - 光照 → 调灯亮度，记录 lux
- 每条都记 `success` + 失败类型 + 耗时

## 5. 安全

- 急停在手边；首次运行限速（末端速度 ≤ 0.1 m/s）
- 关节限位与工作空间软限位在控制器侧，不依赖模型输出
- 每次换任务/换物体后先空跑 3 条确认无碰撞

## 6. 数据校验（入库前）

```bash
python -m kite_real.schema episodes/0000
```

检查：数组形状、NaN、时间戳单调、图像数量与步数一致、`meta.json` 必填字段。
